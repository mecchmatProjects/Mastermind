**Mastermind не конкретна гра з 4 кольорами**, 
а узагальненою математичною моделлю.

# Курсовий проєкт: Generalized Mastermind

## 1. Мета проєкту

Розробити на C++ універсальну програмну реалізацію гри **Mastermind**, 
у якій основні параметри гри не зафіксовані, а задаються користувачем або конфігурацією:

* кількість позицій у секретній комбінації;
* кількість можливих символів/кольорів/ознак;
* можливість повторення символів;
* максимальна кількість спроб;
* режим гри — людина проти програми або програма проти програми.

Основна увага в проєкті приділяється не графічному інтерфейсу, а 
алгоритмічному розв’язанню задачі, структурам даних, комбінаториці та ефективному пошуку секретної комбінації.

---

# 2. Узагальнена математична модель

Нехай задано:

* \(N\) — довжина секретної комбінації;
* \(K\) — кількість можливих символів;
* \(R\) — чи дозволені повторення символів;
* \(M\) — максимальна кількість спроб.

Секретна комбінація має вигляд:

```text
A B C D E ...
```

де кожна позиція містить один із \(K\) можливих символів.

Наприклад:

```text
N = 5
K = 8
repetition = true
```

можлива комбінація:

```text
2 7 7 1 5
```

Якщо повторення заборонені:

```text
2 7 4 1 5
```

---

# 3. Перший етап — модель даних

Визначити, як представити комбінацію в програмі.

Рекомендований базовий варіант:

```cpp
using Code = std::vector<int>;
```

Наприклад:

```cpp
Code secret = {2, 7, 7, 1, 5};
Code guess  = {2, 4, 7, 3, 5};
```

Не рекомендується на першому етапі створювати складну ієрархію класів.

Спочатку потрібно отримати просту і коректну математичну модель.

---

# 4. Параметри гри

Створити окрему структуру конфігурації:

```cpp
struct GameConfig {
    int codeLength;
    int symbolCount;
    bool allowDuplicates;
    int maxAttempts;
};
```

Наприклад:

```cpp
GameConfig config{
    5,
    8,
    true,
    12
};
```

Це означає:

> секретна комбінація має 5 позицій, використовуються 8 можливих символів, повторення дозволені, максимум 12 спроб.

**Важливо:** алгоритми гри не повинні містити чисел типу `4`, `6` або `10`, які припускають конкретну версію Mastermind.

---

# 5. Генерація секретної комбінації

Реалізувати функцію:

```cpp
Code generateSecret(const GameConfig& config);
```

Вона повинна генерувати допустиму секретну комбінацію відповідно до параметрів гри.

Необхідно врахувати два випадки:

### Повторення дозволені

Наприклад:

```text
1 5 5 2 1
```

### Повторення заборонені

Наприклад:

```text
1 5 3 2 7
```

але:

```text
1 5 5 2 7
```

є некоректною.

---

# 6. Перевірка коректності ходу

Створити функцію:

```cpp
bool isValidGuess(
    const Code& guess,
    const GameConfig& config
);
```

Необхідно перевіряти:

1. правильну довжину комбінації;
2. допустимість кожного символу;
3. відсутність повторень, якщо вони заборонені.

Наприклад, при

```text
codeLength = 5
symbolCount = 6
allowDuplicates = false
```

хід

```text
1 3 5 2 4
```

коректний, а

```text
1 3 5 3 4
```

— ні.

---

# 7. Найважливіший алгоритм — оцінювання ходу

Після кожної спроби програма повинна повідомити, наскільки вона близька до секретної комбінації.

Вводимо два показники:

### Exact matches

Кількість символів, які знаходяться **на правильних позиціях**.

Наприклад:

```text
Secret:  1 2 3 4 5
Guess:   1 7 3 8 5
         ↑   ↑   ↑
```

Результат:

```text
3 exact
```

### Partial matches

Символ присутній у секретній комбінації, але знаходиться **не на тій позиції**.

Наприклад:

```text
Secret: 1 2 3 4
Guess:  4 7 2 8
```

Тут:

```text
exact = 0
partial = 2
```

---

# 8. Важливий випадок: повторення

Особливу увагу необхідно приділити повторюваним символам.

Наприклад:

```text
Secret: 1 1 2 3
Guess:  1 2 2 2
```

Не можна просто порахувати кількість однакових значень.

Необхідно враховувати, **скільки разів символ реально присутній у секретній комбінації**.

Тому алгоритм оцінювання повинен працювати коректно як для:

```text
allowDuplicates = false
```

так і для:

```text
allowDuplicates = true
```

---

# 9. Розділення exact та partial matches

Рекомендована схема:

### Крок 1

Знайти всі exact matches.

### Крок 2

Виключити їх із подальшого порівняння.

### Крок 3

Серед решти символів визначити partial matches.

Цей алгоритм студент повинен реалізувати самостійно.

Не слід використовувати готову бібліотеку Mastermind.

---

# 10. Клас результату

Для зручності створити структуру:

```cpp
struct GuessResult {
    int exact;
    int partial;
};
```

Тоді:

```cpp
GuessResult evaluate(
    const Code& secret,
    const Code& guess
);
```

повертає результат перевірки.

Наприклад:

```text
Exact:   2
Partial: 1
```

---

# 11. Базова версія гри

Першою завершеною версією має бути гра:

```text
+--------------------------------+
|       GENERALIZED MASTERMIND   |
+--------------------------------+

Code length: 5
Symbols: 8
Duplicates: yes
Attempts: 12

Enter your guess:
> 1 4 7 2 5

Exact:   2
Partial: 1

Attempts remaining: 11
```

Гра продовжується до:

```text
Exact == CodeLength
```

або вичерпання кількості спроб.

---

# 12. Генералізація простору пошуку

Наступний етап — перейти від **гри людини** до математичної задачі.

Програма повинна вміти побудувати множину всіх можливих комбінацій.

Якщо повторення дозволені:

$$
K^N
$$

можливих кодів.

Якщо повторення заборонені:

$$
K(K-1)(K-2)\ldots(K-N+1).
$$

Наприклад, при:

```text
N = 4
K = 6
duplicates = true
```

існує:

```text
6^4 = 1296
```

можливих кодів.

Цю множину можна використовувати як **простір пошуку**.

---

# 13. Автоматичний гравець

Після реалізації самої гри необхідно створити програму-гравця:

```text
ComputerSolver
```

яка намагається знайти секретну комбінацію.

Після кожної спроби вона отримує лише:

```text
exact
partial
```

і повинна використати цю інформацію для вибору наступного ходу.

---

# 14. Найпростіший Solver

Перший алгоритм:

```text
1. Generate all possible codes.
2. Make a guess.
3. Receive feedback.
4. Remove impossible codes.
5. Select another possible code.
6. Repeat.
```

Наприклад:

```text
Possible codes:

1234
1235
1236
1243
1245
...
```

Після отримання відповіді від Mastermind частина комбінацій стає неможливою.

Тому:

```text
1296 candidates
        ↓
      384
        ↓
       71
        ↓
       12
        ↓
        1
```

Це вже перетворює гру на **задачу комбінаторного пошуку**.

---

# 15. Основна структура Solver

Рекомендовано:

```cpp
class MastermindSolver {
public:
    Code nextGuess(
        const std::vector<Code>& candidates
    );

    void update(
        const Code& guess,
        const GuessResult& result
    );
};
```

Внутрішньо solver повинен зберігати множину можливих рішень.

---

# 16. Евристичний Solver

Для підвищеного рівня складності необхідно реалізувати алгоритм, який вибирає не просто будь-який допустимий код, а **найбільш інформативну наступну спробу**.

Ідея:

```text
Candidate guesses
        ↓
simulate possible answers
        ↓
estimate information
        ↓
choose best guess
```

Для кожної потенційної спроби можна визначити, на скільки груп вона розділяє поточну множину кандидатів.

Наприклад:

```text
Guess A

feedback:
(0,0) → 120 codes
(1,0) → 80 codes
(1,1) → 40 codes
(2,0) → 20 codes
...
```

Хорошою є спроба, яка **рівномірніше розподіляє простір можливих відповідей**.

---

# 17. Порівняння стратегій

У курсовому проєкті потрібно реалізувати щонайменше дві стратегії:

### Strategy 1 — Random

Вибирає випадкову допустиму комбінацію.

### Strategy 2 — Candidate elimination

Вибирає комбінацію з поточної множини можливих рішень.

### Додатково — Information strategy

Вибирає хід, який максимально зменшує очікувану кількість можливих рішень.

---

# 18. Експериментальна частина

Для різних параметрів гри провести серію автоматичних симуляцій.

Наприклад:

|  N |  K | Repetition | Solver      | Avg. guesses |
| -: | -: | ---------- | ----------- | -----------: |
|  3 |  5 | No         | Random      |          ... |
|  3 |  5 | No         | Elimination |          ... |
|  4 |  6 | Yes        | Random      |          ... |
|  4 |  6 | Yes        | Elimination |          ... |
|  5 |  8 | Yes        | Elimination |          ... |

Студент повинен **отримати значення експериментально**, а не вставляти готові результати.

---

# 19. Дослідження складності

Окремо дослідити, як змінюється простір пошуку при збільшенні:

$$
N
$$

та

$$
K.
$$

Наприклад:

```text
N = 4, K = 6
N = 5, K = 6
N = 6, K = 8
N = 7, K = 10
```

Необхідно вимірювати:

* кількість можливих кодів;
* час генерації;
* час фільтрації;
* кількість кандидатів після кожного ходу;
* кількість ходів solver;
* використання пам'яті.

```text
Mastermind

├── Code
```

Це дозволить студенту практично застосувати:

* encapsulation;
* `std::vector`;
* `std::set` / `std::unordered_set`;
* алгоритми STL;
* random number generation;
* polymorphism або templates — для розширеної версії;
* unit testing.

# 21. Мінімальні вимоги курсового

Студент повинен реалізувати:

**1.** Узагальнену конфігурацію Mastermind.

**2.** Генерацію секретної комбінації.

**3.** Перевірку допустимості ходу.

**4.** Коректний алгоритм `exact/partial`.

**5.** Підтримку повторюваних та неповторюваних символів.

**6.** Інтерактивну гру людина ↔ програма.

**7.** Генерацію простору можливих рішень.

**8.** Автоматичного solver на основі elimination.

**9.** Автоматичне тестування solver на великій кількості ігор.

**10.** Експериментальне дослідження залежності складності від \(N\), \(K\) та інших параметрів.

# 22. Завдання підвищеної складності

Для сильного студента можна додати:

* information-theoretic solver;
* мінімізацію середньої кількості ходів;
* мінімізацію worst-case кількості ходів;
* parallel simulation великої кількості партій;
* GUI;
* збереження статистики;
* підтримку різних типів feedback;
* власний формат конфігурації;
* порівняння різних стратегій автоматичного гравця.

Особливо цікавим математичним розширенням буде дослідження питання:

> **Яку наступну комбінацію слід вибрати, щоб отримати максимум інформації про секретний код?**
