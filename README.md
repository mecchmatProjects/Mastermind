# Generalized Mastermind

**Generalized Mastermind** - логічна гра, у якій потрібно відгадати секретний код за обмежену кількість спроб. Після кожного ходу гравець отримує підказки: скільки символів стоять на правильних місцях і скільки є в коді, але розташовані інакше.

Проєкт реалізовано мовою **C++17** із консольним і графічним інтерфейсами. Можна відгадувати код самостійно або покроково спостерігати за грою комп'ютера. Окрема частина проєкту присвячена порівнянню алгоритмів пошуку секретного коду та дослідженню їхньої ефективності.

## Можливості

- Генерація секретного коду з повторами символів або без них.
- Перевірка введених комбінацій і коректне обчислення підказок `Exact` та `Partial`.
- Три рівні складності: Easy, Medium і Hard.
- Власні параметри гри в консольному режимі, де код відгадує людина.
- Графічний інтерфейс на SFML 3 з історією ходів і кольоровими позначеннями символів.
- Три стратегії автоматичного гравця: Random, Elimination та Information.
- Автоматичні симуляції, статистика і дослідження простору пошуку.
- Шість наборів автоматичних тестів.

У консольній та графічній грі комп'ютер використовує **Elimination**. Порівняння всіх трьох стратегій виконується окремою програмою `Experiments`.

## Правила гри

Секретний код складається з чисел від `1` до `K`. Потрібно відгадати і значення символів, і порядок їхнього розташування.

Після кожної допустимої спроби програма повідомляє:

| Підказка | Значення |
| --- | --- |
| `Exact` | Кількість символів, що збігаються із секретним кодом і значенням, і позицією |
| `Partial` | Кількість інших символів, що є в секретному коді, але стоять на інших позиціях |

Наприклад, для секретного коду `1 2 3 4` і спроби `1 4 2 5` результат буде `Exact: 1`, `Partial: 2`: число `1` стоїть на своєму місці, а `4` і `2` присутні в коді на інших позиціях.

Кожен символ секретного коду враховується лише один раз. Наприклад, для секрету `1 1 2 3` і спроби `1 2 2 2` результат - `Exact: 2`, `Partial: 0`.

Гравець перемагає, коли `Exact` дорівнює довжині коду. Якщо спроби закінчилися, гра завершується поразкою й показує секретний код. Некоректне введення не витрачає спробу.

### Параметри та рівні складності

| Параметр | Поле конфігурації | Значення |
| --- | --- | --- |
| `N` | `codeLength` | Довжина коду |
| `K` | `symbolCount` | Кількість можливих символів: від `1` до `K` |
| Повтори | `allowDuplicates` | Чи може один символ зустрічатися кілька разів |
| Ліміт спроб | `maxAttempts` | Максимальна кількість допустимих ходів |

Довжина коду, кількість символів і ліміт спроб мають бути додатними. Якщо повтори заборонені, необхідно, щоб `N <= K`.

| Рівень | Довжина коду | Кількість символів | Повтори | Спроб |
| --- | ---: | ---: | --- | ---: |
| Easy | 3 | 4 | Ні | 10 |
| Medium | 4 | 6 | Так | 10 |
| Hard | 5 | 8 | Так | 8 |

Режим **Custom** доступний лише в консольній грі, коли код відгадує людина. У графічному інтерфейсі доступні три готові рівні складності.

## Завантаження проєкту

Встановіть Git, відкрийте термінал і виконайте:

```bash
git clone https://github.com/mecchmatProjects/Mastermind.git
cd Mastermind
```

## Консольна версія

Потрібні компілятор із підтримкою **C++17** та **CMake 3.20 або новіший**. SFML для консольної версії, тестів та експериментів не потрібна.

Встановіть інструменти розробника Apple, якщо їх ще немає:


```bash
brew install cmake
```

Зберіть і запустіть гру:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --target Mastermind
./build/Mastermind
```

Встановіть інструменти збирання:


Перевірте, що `cmake --version` показує версію не нижче 3.20, після чого виконайте:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug

./build/Mastermind
```

Встановіть **Visual Studio 2022** з компонентом **Desktop development with C++**, а також Git і CMake 3.21 або новіший. Відкрийте PowerShell у папці проєкту:

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64

.\build\Debug\Mastermind.exe
```

### Як грати в консолі

1. Оберіть режим: `1` - відгадуєте ви, `2` - відгадує комп'ютер.
2. Оберіть складність: `1` - Easy, `2` - Medium, `3` - Hard. У режимі `1` також доступний пункт `0` - Custom.
3. Якщо відгадуєте самостійно, вводьте рівно `N` чисел через пробіл, наприклад `1 4 2 3` для коду довжини 4.
4. Використовуйте підказки `Exact` і `Partial`, щоб обрати наступну спробу.

Для Custom введіть чотири значення через пробіл: довжину коду, кількість символів, дозвіл повторів (`0` - ні, `1` - так) і ліміт спроб. Наприклад:

```text
5 8 1 12
```

Це код довжини 5 із символами від 1 до 8, з дозволеними повторами та лімітом 12 спроб.

У режимі комп'ютера програма сама генерує секретний код, обчислює підказки й показує послідовність ходів автоматичного гравця.

## Графічна версія

Для GUI додатково потрібна **SFML 3**. Використовуйте CMake 3.28 або новіший для наведених нижче інструкцій; окремі пакети залежностей можуть мати власні вимоги. Графічна версія вмикається параметром `MASTERMIND_BUILD_GUI=ON`.

### macOS

Після встановлення інструментів розробника Apple та Homebrew виконайте:

```bash
brew install cmake sfml
cmake -S . -B build-gui -DCMAKE_BUILD_TYPE=Debug -DMASTERMIND_BUILD_GUI=ON \
  -DCMAKE_PREFIX_PATH="$(brew --prefix sfml)"
cmake --build build-gui --target MastermindGUI
./build-gui/gui/MastermindGUI
```

### Windows (Visual Studio 2022, x64)

Встановіть Visual Studio 2022 з компонентом **Desktop development with C++**, Git і CMake. Для встановлення SFML використовується [vcpkg](https://github.com/microsoft/vcpkg).

У PowerShell виконайте одноразове встановлення залежності:

```powershell

git clone https://github.com/microsoft/vcpkg.git "$mastermindVcpkg"
& "$mastermindVcpkg\bootstrap-vcpkg.bat"
& "$mastermindVcpkg\vcpkg.exe" install "sfml[graphics]:x64-windows" --no-default-features
```

Якщо vcpkg уже встановлено, задайте в `$mastermindVcpkg` шлях до наявної папки та виконайте команду встановлення SFML, пропустивши клонування й початкове налаштування.

У тому самому вікні PowerShell, перебуваючи в папці Mastermind, зберіть гру:

```powershell
cmake -S . -B build-gui -G "Visual Studio 17 2022" -A x64 `
  -DMASTERMIND_BUILD_GUI=ON `
  "-DCMAKE_TOOLCHAIN_FILE=$mastermindVcpkg/scripts/buildsystems/vcpkg.cmake" `
  -DVCPKG_TARGET_TRIPLET=x64-windows
cmake --build build-gui --config Debug --target MastermindGUI
.\build-gui\gui\Debug\MastermindGUI.exe
```

Якщо у вашому дистрибутиві доступний пакет **SFML 3**, установіть його разом з інструментами збирання. Наприклад, для Arch Linux:

### Поширені проблеми запуску

| Проблема | Що перевірити |
| --- | --- |
| CMake не знаходить SFML | Потрібна версія 3; перевірте `CMAKE_PREFIX_PATH` або шлях до toolchain vcpkg |
| Не знайдено компілятор | На macOS установіть Command Line Tools, на Windows - компонент C++, на Linux - інструменти збирання |
| `Could not load the Mastermind font` | Має бути доступний файл `gui/assets/Barlow-SemiBold.ttf`; після переміщення вихідної папки повторно налаштуйте і зберіть проєкт |

Шлях до шрифту записується під час збирання. Для запуску перенесеного на інший комп'ютер проєкту потрібно повторити збирання з вихідного коду.

## Стратегії автоматичного гравця

| Стратегія | Принцип роботи |
| --- | --- |
| **Random** | Генерує всі допустимі коди, перемішує їх і пропонує по черзі без повторного використання. Отримані підказки не враховує |
| **Elimination** | Зберігає коди, сумісні з усіма отриманими підказками. Наступною спробою обирає перший код із цієї множини |
| **Information** | Фільтрує кандидатів і вибирає спробу, яка краще розділяє їх за можливими підказками |

Для Information оцінюється до **100 пробних кодів**, узятих із поточної множини кандидатів із рівномірним кроком. Для кожного пробного коду кандидати розподіляються на групи за відповіддю `(Exact, Partial)`. Обирається код із найменшою сумою квадратів розмірів цих груп. Такий критерій мінімізує очікувану кількість кандидатів після відповіді за умови їхньої рівноймовірності.

Обмеження вибірки зменшує час пошуку ходу, але не гарантує вибору найкращої спроби серед усіх можливих кодів.

## Експерименти

Програма `Experiments` порівнює три стратегії, а `Complexity` досліджує розмір простору пошуку, час генерації й фільтрації, оцінку пам'яті та кількість кандидатів після ходів Elimination.

Після налаштування папки `build` зберіть і запустіть їх.

macOS / Linux:

```bash
cmake --build build --target Experiments Complexity
./build/Experiments
./build/Complexity
```

Windows, генератор Visual Studio:

```powershell
cmake --build build --config Debug --target Experiments Complexity
.\build\Debug\Experiments.exe
.\build\Debug\Complexity.exe
```

### Методика

- Для кожної конфігурації один раз генерується список секретів. Усі три стратегії грають проти цього самого списку.
- Ліміт становить **12 спроб** для кожної гри. Це налаштування експериментів, яке відрізняється від готових рівнів інтерактивної гри.
- Кількість ігор: **200** для `N=3, K=5` без повторів, **100** для `N=4, K=6` з повторами та **15** для `N=5, K=8` з повторами.
- `Avg` - середня кількість використаних спроб за всіма іграми; для нерозв'язаних ігор враховується ліміт 12. `AvgWin` - середнє лише за виграними іграми; за відсутності перемог програма виводить `0.00`.
- Час вимірюється для всієї серії однієї стратегії, включно зі створенням розв'язувача для кожної гри.
- Початковий стан генераторів задається через `std::random_device`, тому результати повторних запусків можуть відрізнятися.

### Результати порівняння

Нижче наведено результати одного попереднього запуску. Час залежить від комп'ютера, компілятора й режиму збирання; наведені значення не є гарантією швидкодії на іншому пристрої.

| N | K | Повтори | Стратегія | Ігор | Розв'язано, % | Сер. спроб | Макс. спроб | Час серії, мс |
| --- | --- | --- | --- | ---: | ---: | ---: | ---: | ---: |
| 3 | 5 | Ні | Random | 200 | 22.00 | 10.86 | 12 | 8.03 |
| 3 | 5 | Ні | Elimination | 200 | 100.00 | 3.31 | 5 | 15.88 |
| 3 | 5 | Ні | Information | 200 | 100.00 | 3.28 | 4 | 566.68 |
| 4 | 6 | Так | Random | 100 | 0.00 | 12.00 | 12 | 47.84 |
| 4 | 6 | Так | Elimination | 100 | 100.00 | 5.64 | 9 | 212.56 |
| 4 | 6 | Так | Information | 100 | 100.00 | 4.40 | 6 | 13247.18 |
| 5 | 8 | Так | Random | 15 | 0.00 | 12.00 | 12 | 182.37 |
| 5 | 8 | Так | Elimination | 15 | 100.00 | 7.53 | 9 | 1023.03 |
| 5 | 8 | Так | Information | 15 | 100.00 | 5.27 | 6 | 63422.69 |

У цьому запуску Elimination та Information розв'язали всі ігри. Information у середньому потребувала менше спроб, проте витрачала більше часу на вибір ходу. Random показала гірші результати за такого ліміту спроб, оскільки не використовує підказки.

Для найбільшої конфігурації проведено лише 15 ігор, тому висновки за нею попередні. Відсоток перемог у цих серіях не гарантує такого самого результату для кожного секретного коду.

## Дослідження складності

Кількість допустимих кодів визначається параметрами гри:

- з повторами: **K^N**;
- без повторів: **K! / (K - N)!**, де `N <= K`.

Наприклад, для `N=4, K=6` існує 1296 кодів із повторами та 360 без повторів.

### Простір пошуку

Результати попереднього запуску `Complexity`:

| N | K | Повтори | Кодів | Генерація, мс | Оцінка пам'яті, МіБ | Фільтрація, мс | Залишилось кодів |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: |
| 4 | 6 | Ні | 360 | 0.13 | 0.01 | 0.42 | 9 |
| 4 | 6 | Так | 1296 | 0.35 | 0.05 | 1.25 | 20 |
| 5 | 6 | Так | 7776 | 2.15 | 0.33 | 8.50 | 25 |
| 5 | 8 | Ні | 6720 | 2.21 | 0.28 | 9.82 | 44 |
| 5 | 8 | Так | 32768 | 10.38 | 1.38 | 39.00 | 35 |
| 6 | 8 | Так | 262144 | 73.15 | 12.00 | 336.88 | 42 |
| 6 | 10 | Ні | 151200 | 45.34 | 6.92 | 241.22 | 265 |
| 7 | 10 | Так | 10000000 | - | 495.91 | - | - |

Для таблиці фільтрація виконується за однією відповіддю: спробою є перший згенерований код, а секретом - код посередині списку. Це окреме вимірювання фільтрації, а не повна партія.

Пам'ять оцінюється за формулою `кількість кодів * (sizeof(std::vector<int>) + N * sizeof(int))`, без додаткових витрат алокатора й резервної місткості векторів. Значення обчислюються в МіБ, хоча програма підписує колонку `Memory(MB)`. Оцінка залежить від платформи.

Якщо кількість кодів перевищує **2 000 000**, `Complexity` пропускає їхню генерацію. Для `N=7, K=10` наведено лише теоретичну кількість кодів та оцінку пам'яті.

### Кандидати після ходів Elimination

Обидві конфігурації в цій таблиці допускають повтори.

| Хід | N=4, K=6: серія з 50 ігор | N=5, K=8: серія з 10 ігор |
| --- | ---: | ---: |
| 0 | 1296.0 | 32768.0 |
| 1 | 487.4 | 13925.8 |
| 2 | 153.8 | 5270.4 |
| 3 | 33.9 | 1132.5 |
| 4 | 6.7 | 321.6 |
| 5 | 1.6 | 66.3 |
| 6 | 1.3 | 8.4 |
| 7 | - | 1.9 |
| 8 | - | 1.5 |

Хід 0 відповідає початковому простору пошуку. Після кожного невдалого ходу обчислюється середня кількість кандидатів лише серед ігор, які ще тривають; завершені партії до цього середнього не входять.

### Висновки щодо складності

- За дозволених повторів додавання однієї позиції збільшує кількість кодів у `K` разів. Тому генерація та зберігання всього простору пошуку швидко стають витратними.
- Elimination скорочує множину кандидатів після кожної отриманої підказки, не перебираючи несумісні коди на наступних ходах.
- Для `M` поточних кандидатів Information оцінює до `min(100, M)` пробних кодів. Кожен порівнюється з усіма кандидатами. За середньої лінійної вартості `evaluate` це приблизно `O(min(100, M) * M * N)` на вибір ходу; за повної оцінки всіх кандидатів - `O(M^2 * N)`.
- Менша кількість спроб не обов'язково означає менший час роботи: Information витрачає додаткові обчислення на вибір кожного ходу.

`Complexity` також виводить пікову пам'ять усього процесу. Це окремий показник, який не дорівнює оцінці пам'яті масиву кодів. Вимірювання пікової пам'яті реалізовано для macOS і Linux; на Windows програма повідомляє, що воно недоступне.
